## Phase Goal

**As an** operator, **I want to** review and approve AI-proposed remediation commands when a failure occurs, with a strict 2-cycle cap on recovery attempts, **so that** the shell assists in repairing issues safely without thrashing or causing cascading system damage.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Remediation Engine → Host Execution | Remediation commands alter system state to fix failures and must not run unconfirmed |
| Remediation Loop → Process Recursion | Multi-cycle failure recovery could cascade into infinite repair attempts or flapping commands |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-06-04 | Elevation of Privilege | SafetyGate Remediation Bypass | critical | mitigate | Every remediation proposal must pass through SafetyGate.process_proposal requiring explicit [y/N/e] operator confirmation; no automated unconfirmed execution is permitted per D-02. |
| T-06-05 | Denial of Service | Remediation Infinite Loop | high | mitigate | RemediationController strictly enforces MAX_REMEDIATION_CYCLES = 2 per D-03; upon reaching 2 attempts, automated recovery halts with an explicit warning and control returns to the user. |

</threat_model>
