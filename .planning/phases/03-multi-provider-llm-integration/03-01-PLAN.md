## Phase Goal

**As a** system administrator or developer, **I want to** generate structured shell command proposals with categorized risk tiers and receive clear, actionable remediation when providers are misconfigured or offline, **so that** I can operate safely and resolve setup issues without deciphering raw stack traces.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM Raw Response → Parser | Untrusted raw string generated by external LLM parsed into structured command |
| Environment Config / Secrets → Error Messages | API keys and tokens must not be echoed in error messages or exception strings |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | Proposal Parser | high | mitigate | Dual-mode parsing validates JSON strictly against Pydantic schema and falls back to bounded regex extraction, preventing arbitrary object injection. |
| T-03-02 | Information Disclosure | Error Hierarchy | high | mitigate | Exception formatters in errors.py sanitize credentials and output only missing variable names (e.g. GEMINI_API_KEY) without printing environment secrets. |
